# Pull Request Template

Ask the user before opening a pull request. One branch, one pull request. Open
pull requests sequentially, in the order their changes depend on each other, and
merge them in that same order.

## Title

The title is human readable prose, not a commit subject.

* Write it as a short statement a reader understands without knowing the
  convention: `Add index routing system`, `Breaking Change`,
  `Update license year to 2026`.
* Do NOT use the Conventional Commits form. No `feat:`, no `fix:`, no
  `docs(agents):`. That convention governs commit subjects only, per
  [`commit-conventions.md`](commit-conventions.md).
* Capitalize the first word. No trailing period. No issue tracker identifiers.

## Body

```
## Summary

One paragraph on what this changes and why.

## Changes

- One bullet per logical change, in the order the commits make them.
- Name the files or areas touched, not every line.

## Verification

- What was checked, and how. State plainly if something was not verified.

## Notes

- Anything a reviewer needs that the diff does not show. Omit the section when
  there is nothing.
```

## Never Include

* A session link, an assistant conversation URL, or any link back to the tool used
  to write the change.
* A generated by or co authored by footer naming a tool, unless the user asks for
  one.
* Credentials, tokens, environment variable values, or internal hostnames.
* Issue or pull request references with `#`, matching the commit rule.

## Before Opening

1. Confirm the branch follows [`branching-strategy.md`](branching-strategy.md).
2. Confirm every commit follows [`commit-conventions.md`](commit-conventions.md).
3. Confirm the owning index was updated for every file added or removed, per
   [`../creators/index-creator.md`](../creators/index-creator.md).
4. Review the full diff against the default branch.
5. Ask the user.
